DDDのアーキテクチャのイメージ

```bash
/project-root
├── cmd/
│   └── api/
│       └── main.go            # エントリポイント
├── internal/
│   ├── domain/
│   │   └── user/
│   │       ├── entity.go      # User エンティティ
│   │       ├── value.go       # Emailなどの値オブジェクト
│   │       └── repository.go  # UserRepository インターフェース
│   ├── application/
│   │   └── user/
│   │       ├── usecase.go     # ユースケース（例: RegisterUser）
│   │       └── dto.go         # 入出力 DTO
│   ├── interface/
│   │   ├── handler/
│   │   │   └── user_handler.go # HTTPハンドラ（EchoやChiなどを想定）
│   │   └── router.go          # ルーティング設定
│   └── infrastructure/
│       ├── persistence/
│       │   └── user_repo.go   # DB実装（MySQL, PostgreSQLなど）
│       ├── external/          # 外部APIクライアント（必要なら）
│       └── config/            # 設定・環境変数読み込み
└── pkg/
    ├── logger/                # ログ共通処理
    ├── errors/                # エラーハンドリング
    └── util/                  # 共通ユーティリティ
```
